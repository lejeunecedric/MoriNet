<objective>
Extract the four MCP read bodies (`list_vaults`, `list_notes`, `read_note`, `search_notes`) out of `src/mcp.rs` into shared `pub(crate)` helpers in a new `src/api.rs`, with a typed error enum, and reduce the MCP tools to thin wrappers. This single-sources ACL logic (D-04) so the wave-2/3 REST endpoints cannot drift from MCP behavior — the foundation for API-02/03/04 and the 404-not-403 rule (D-02).
</objective>

<context>
- Phase context: 16-CONTEXT.md (D-02, D-04, D-05, D-08, D-10), 16-PATTERNS.md §3 §9 (verbatim body excerpts + test-string warning).
- `src/mcp.rs` is 647 lines — safe to read whole. `src/server.rs` is ~9475 lines: NEVER whole-file read; use grep anchors + windowed reads if referenced.
- Discretion decisions made by planner (executor follows, does not re-decide):
  - **Helper location:** new `src/api.rs` (module declared in `src/lib.rs` alphabetically before `pub mod browse;`). The already-`pub(crate)` free helpers `safe_join` (mcp.rs:20-34), `list_md_files` (mcp.rs:39-65), `search_md` (mcp.rs:78-103) and DTO `Hit` (mcp.rs:68-74) STAY in mcp.rs — api.rs calls them via `crate::mcp::…` (16-PATTERNS §3: "no move needed").
  - **Error vocabulary:** `pub(crate) enum ApiReadError { NotFound, InvalidPath, NoSuchFolder, NoSuchNote, Unreadable }` in api.rs. MCP wrapper maps: NotFound → `"vault not found or access denied"` (asserted verbatim at mcp.rs:601,626), InvalidPath → `"invalid path"`, NoSuchFolder → `"no such folder"`, NoSuchNote → `"no such note"`, Unreadable → whatever string `read_note` currently emits on read failure (executor reads mcp.rs:238-260 and preserves it exactly).
  - **Access logging for REST:** DECISION = **skip REST access logging in v1.** `migrations/0008_*.sql:27` CHECK-constrains `access_log.source` to `('web','mcp')`; a `'api'` value needs a SQLite table-rebuild migration for a best-effort feature no API-0x requirement asks for, and reusing `'mcp'`/`'web'` would misattribute REST traffic in stats (worse than silence). MCP's own `log_access` (mcp.rs:170-180) is untouched. Rationale recorded here and in 16-05.
  - **read_note helper returns bytes** (`Vec<u8>`), not String — REST needs raw bytes for `webdav::etag_of` (wave 3); the MCP wrapper converts to String and maps non-UTF-8/read errors to the preserved MCP string.
</context>

<threat_model>
  <threat stride="Spoofing/Information Disclosure" severity="high">
    ACL bypass via helper drift (B1): if REST later re-implemented vault resolution instead of calling the helpers, hidden/revoked shares could leak. Mitigation: this plan makes api.rs helpers the ONLY vault-resolution path (D-04); MCP keeps zero inline ACL logic after the refactor; the ported matrix (16-05) and existing tools_are_acl_scoped pin the behavior.
  </threat>
  <threat stride="Information Disclosure" severity="medium">
    Existence leak via error differentiation (D-02): a distinct "forbidden" reason would reveal vault existence. Mitigation: single `NotFound` reason covers unknown slug AND no-access (same as legacy `source_dir` returning None); tests assert the identical string for both.
  </threat>
  <threat stride="Tampering" severity="medium">
    Path traversal via `path`/`sub` params: mitigated by reusing `crate::mcp::safe_join` unchanged inside the helpers (canonicalize + prefix check); `read_note_refuses_traversal_even_with_access` stays green unedited.
  </threat>
  <threat stride="Information Disclosure" severity="low">
    Serving build output instead of source (B3): helpers resolve dirs only via `crate::webdav::source_dir_of` — the mdBook source tree, never the generated `book/` output (D-06). No new path resolution is introduced.
  </threat>
</threat_model>
