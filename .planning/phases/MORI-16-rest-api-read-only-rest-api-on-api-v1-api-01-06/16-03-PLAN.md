<threat_model>
  <threat stride="Tampering/Information Disclosure" severity="high">
    Path traversal via the `{*path}` wildcard (B1-adjacent): wildcards hand raw user-controlled relative paths to the filesystem. Mitigation: the ONLY resolution is the existing `crate::mcp::safe_join` inside the 16-01 helper (canonicalize + prefix containment — same primitive as WebDAV); no new join/canonicalize code in api.rs; tests cover raw `..`, percent-encoded `%2e%2e`, and absolute-path shapes, all → 404.
  </threat>
  <threat stride="Information Disclosure" severity="high">
    Serving build output instead of source (B3/D-06): a handler resolving through the mdBook `book/` tree would leak generated/stale content and bypass source ACL semantics. Mitigation: bytes come exclusively from the 16-01 `read_note` helper whose dir comes from `webdav::source_dir_of`; test asserts body == source file bytes.
  </threat>
  <threat stride="Information Disclosure" severity="medium">
    Existence leak via status differentiation on path reads (D-02/B1): 403 for hidden shares or 400-vs-404 differentiation for traversal would confirm vault/note existence. Mitigation: NotFound, NoSuchNote and InvalidPath all collapse to 404 problem+json not_found on the REST mapping; hidden-share test asserts the exact 404 shape.
  </threat>
  <threat stride="Denial of Service" severity="medium">
    DoS via `limit` param (huge limit → whole-tree listing) or unbounded cursor loops. Mitigation: hard clamp 200 (D-09), limit+1 fetch strategy, cursor decode is O(1) skip over an in-memory sorted vec; search is capped at 50 by search_md (D-10). Test asserts `?limit=500` behaves as 200.
  </threat>
  <threat stride="Repudiation/Caching correctness" severity="medium">
    Cache poisoning / stale-serve via weak or malformed If-None-Match: a parser that degraded `W/` or garbage to Absent would serve 200 bodies to conditional clients that expected precondition enforcement. Mitigation: reuse the Phase 15 fail-closed `if_none_match_of` verbatim; Malformed → 400 before any body (D-12); strong ETag only (quoted sha256, never W/).
  </threat>
</threat_model>
