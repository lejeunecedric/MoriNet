<threat_model>
  <threat id="T-18-08" stride="Information Disclosure" severity="high">
    The export route could zip files OUTSIDE the vault source dir (symlink planted in a synced vault, or `..` path tricks) — arbitrary file read by any user with vault read access. Mitigation: canonicalize-each-file + starts_with(src) guard rejects symlink escapes; dot-dirs excluded; the walk root is always `webdav::source_dir_of(book_path)` derived from the DB, never from the request. Tests: `bundle_zip_rejects_symlink_escape`, `bundle_zip_skips_dot_dirs`, `export_zip_requires_access`.
  </threat>
  <threat id="T-18-09" stride="Information Disclosure" severity="medium">
    Answering 403 vs 404 (or a different error for unknown-slug vs no-access) lets an attacker enumerate private vault slugs through the export endpoint. Mitigation: single collapsed 404 shape for store-error, unknown slug, no access, and missing source (D-06 / Phase 16 rule; PATTERNS §6 divergence explicitly followed). Tests: `export_zip_requires_access`, `export_zip_unknown_vault_404` assert identical 404 body.
  </threat>
  <threat id="T-18-10" stride="Denial of Service" severity="medium">
    A huge vault source (or zip-bomb-shaped tree) turns export into unbounded-memory exhaustion (zip is built in-memory per D-06's simplicity call). Mitigation: MAX_EXPORT_ENTRIES (20 000) + MAX_EXPORT_BYTES (256 MiB) caps checked DURING the walk before buffering; failure answers an error page, no partial zip. Tests: `bundle_zip_entry_cap_enforced` (constants pinned), `bundle_zip_entries_byte_identical` (bounded happy path).
  </threat>
  <threat id="T-18-11" stride="Tampering" severity="low">
    Dependency risk: the one permitted archive crate could drag in the banned extra codecs (zstd/xz/bzip2) or a second TLS stack. Mitigation: `default-features = false, features = [\"deflate\"]` (PATTERNS §10 audit + checker re-verify on zip 9.4.1: deflate ⇒ flate2 + zopfli only, no TLS, no async runtime; banned-codec gate is bzip2/zstd/xz/lzma); comment rescope keeps the one-crate-per-milestone policy auditable. Tests: `cargo tree -p zip` grep gate (empty for bzip/zstd/xz/lzma).
  </threat>
</threat_model>
