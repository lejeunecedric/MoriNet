<threat_model>
  <threat id="T-18-05" stride="Denial of Service" severity="medium">
    A slow or failing OKF scan inside refresh/register could block or break the user-facing refresh flow (D-02 violation). Mitigation: scan is best-effort in the record_vault_changes shape — errors only eprintln, the redirect is byte-identical; the single set_vault_okf write happens only after a complete scan so failures leave previous stats untouched. Tests: `okf_scan_helper_skips_missing_source_dir`, plus existing refresh-flow tests (`cargo test --lib refresh`) unchanged and green.
  </threat>
  <threat id="T-18-06" stride="Tampering" severity="medium">
    Corrupted/hostile okf_json in the DB (or a hand-edited DB) could inject HTML into the badge (XSS via vault metadata). Mitigation: badge text is built ONLY from serde-typed integers and the fixed version literals "0.1"/"0.2" — no free-text from the JSON reaches HTML; unparseable JSON renders empty. Tests: `okf_badge_html_unparseable_is_empty`, `okf_badge_html_v02_string_exact`.
  </threat>
  <threat id="T-18-07" stride="Information Disclosure" severity="low">
    The badge on vault cards could leak conformance data to users without access. Mitigation: vault_row only renders for vaults already filtered by `accessible_vaults` (existing ACL); vault_okf adds no new visibility axis. Tests: existing accessible_vaults ACL tests stay green; `home_page_no_badge_when_never_scanned`.
  </threat>
</threat_model>
