  - **Scan walk:** reuse `crate::mcp::list_md_files(dir)` for the file list (relative paths, hidden dirs skipped). Reserved = exactly the root-relative paths `"index.md"` and `"log.md"` (case-sensitive). Unreadable/non-UTF8 files count in `total` but never in `concepts` (best-effort, D-02 spirit — a scan never panics on bad bytes).
  - **Threshold:** bundle ⇔ `total > 0 && concepts * 100 >= total * 80` (integer math, exactly D-03's "< 80% ⇒ not a bundle").
  - **v0.2 presence set:** `generated`, `verified`, `sources`, `status`, `stale_after` — presence = `fm.has(key)` (see accessor below). Nested maps (`generated: {by, at}`) parse as an empty-or-leaked List — presence of the KEY is all D-04 requires ("opaque presence flags").
  - **`has()` accessor (the ONLY frontmatter.rs change):** `pub fn has(&self, key: &str) -> bool { self.fields.contains_key(key) }` — a read-only view of already-parsed state; parsing behavior, contract comments, and every existing test are untouched. Justification vs D-04: D-04 forbids a YAML dependency and parser extension; `has()` extends neither — without it, `verified:`/`generated:` block-map presence is undetectable through `scalar()`/`list()` alone (both return empty for an empty List field).
  - **trust_tier algorithm:** `present = fm.has("verified")`; if `!present` ⇒ `"unverified"`; else collect candidates = `fm.list("verified")` items ∪ `fm.scalar("verified")`; any candidate containing the substring `"human:"` ⇒ `"human-reviewed"` (works because block-list-of-maps yields items like `"by: human:alice"`, frontmatter.rs:97-100); else ⇒ `"machine-confirmed"`. Return type `&'static str`.
  - **`note_meta(fm: &Frontmatter) -> serde_json::Value`:** `{"type": fm.page_type(), "tags": fm.list("tags"), "status": fm.scalar("status"), "trust_tier": trust_tier(fm)}` — nulls serialize as JSON null (D-07 field set).
  - **`pub fn frontmatter_of(bytes: &[u8]) -> Option<Frontmatter>`:** `String::from_utf8` ok ⇒ `split(&s).0` if `!is_empty()` else `None` — the shared "no frontmatter ⇒ null" rule (D-07) in one place for 18-05/18-06.

  </threat>
  <threat id="T-18-02" stride="Spoofing" severity="medium">
    A crafted frontmatter could fake a higher trust tier (e.g. `verified: human:…` injected by an untrusted vault author) — accepted: OKF trust fields are author-declared by spec; MoriNet only DERIVES the tier label, it never grants access from it. Mitigation: trust_tier is display/metadata-only (enforced by design — no auth code path may call it; ACLs stay in store.access_for). Tests: `trust_tier_*` pin the derivation so it cannot silently widen.
  </threat>
