<threat_model>
  <threat id="T-17-20" stride="Spoofing/Tampering" severity="high">
    Regression drift: individual wave tests pass but a composed attack path (e.g. forged state + replayed code + hostile pre-set cookie chained) slips through per-plan test silos. Mitigation: this plan's matrix composes the full HTTP surface per A-family with auth_events assertions; any gap found is fixed in the owning module, never by weakening the matrix. Tests: the entire `matrix_a1_*`/`matrix_a2_*` families.
  </threat>
  <threat id="T-17-21" stride="Authorization bypass" severity="high">
    A7 residual: a provisioned or SSO-linked user reaches admin surfaces or a 403 response leaks a session cookie. Mitigation: matrix asserts gate refusal for provisioned readers AND absence of `Set-Cookie: morinet_session` on every refusal path; disabled-config 404s prove removability. Tests: `matrix_a7_provisioned_reader_blocked_from_admin`, `matrix_a7_unmatched_email_gets_no_cookie`, `matrix_a7_sso_disabled_routes_404`.
  </threat>
  <threat id="T-17-22" stride="Spoofing" severity="high">
    A6 residual: a hostile cookie set before/during the flow survives into the authenticated session (fixation). Mitigation: callback always mints a fresh signed cookie (replacing any pre-existing one) and matrix proves it; require_session never sees pre-auth identifiers. Tests: `matrix_a6_fresh_cookie_on_sso_login`, `matrix_a6_no_preauth_identifier`.
  </threat>
  <threat id="T-17-23" stride="Repudiation" severity="medium">
    Refusals that are not logged leave attacks invisible to operators. Mitigation: every matrix refusal asserts its auth_events row (kind+detail), making "every link/deny is logged" (D-05) mechanically enforced across families. Tests: auth_events assertions embedded in each matrix refusal test.
  </threat>
  <threat id="T-17-24" stride="Denial of Service" severity="low">
    Documented-but-misconfigured deployments (e.g. admin group mapping + present-empty claim) demote users unexpectedly. Mitigation: docs state replace-on-login semantics and the last-admin guard explicitly; admin mapping documented as opt-in with the fail-closed absent-claim rule. Accepted residual: operators can still misconfigure — bounded by the guard + audit log. Tests: docs grep gates here; behavior pinned by 17-04's `group_sync_last_admin_kept`.
  </threat>
</threat_model>
