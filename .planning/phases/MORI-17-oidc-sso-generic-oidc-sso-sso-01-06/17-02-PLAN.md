<threat_model>
  <threat id="T-17-05" stride="Tampering/Spoofing" severity="high">
    CSRF on /sso/callback (A2): attacker feeds a victim a callback URL with their own code, linking the victim's session to the attacker's IdP account. Mitigation: state generated per flow start, signed short-lived cookie, constant-time compare, single-use via cookie clear; every mismatch refuses with no session. Tests: `sso_callback_rejects_missing_state_cookie`, `sso_callback_rejects_forged_state_cookie`, `sso_callback_rejects_state_mismatch`, `sso_callback_rejects_replayed_callback`.
  </threat>
  <threat id="T-17-06" stride="Spoofing" severity="high">
    ID-token injection / mix-up (A2): a token from another client or a replayed token accepted. Mitigation: nonce generated per flow, embedded in the ID token validation (`claims.nonce == stored nonce`), aud must contain client_id, iss must equal configured issuer — all fail-closed with deny log. Tests: `sso_callback_rejects_nonce_mismatch`, `sso_callback_rejects_bad_aud`, `sso_callback_rejects_wrong_signing_key`.
  </threat>
  <threat id="T-17-07" stride="Spoofing" severity="high">
    Unsigned or foreign-key-signed ID token accepted (no JWKS validation) = trivial auth bypass. Mitigation: validation ONLY through openidconnect's `IdTokenClaims::verify` against the discovery-fetched JWKS; alg pinned RS256 via CoreIdToken; access token/userinfo never consulted for identity. Tests: `sso_callback_rejects_wrong_signing_key` (forged with throwaway key), `sso_callback_happy_path_mints_session_cookie` (proves the validated path works).
  </threat>
  <threat id="T-17-08" stride="Interception" severity="medium">
    PKCE downgrade (plain challenge or verifier omitted) enables code interception. Mitigation: S256 only (no plain path exists in code), verifier stored in the signed state cookie and always sent; mock IdP refuses exchange without a matching verifier. Tests: `sso_login_redirects_with_pkce_s256_and_state_cookie`, `sso_callback_requires_pkce_verifier`.
  </threat>
  <threat id="T-17-09" stride="Tampering" severity="high">
    Session fixation / parallel session mechanism (A6): a callback-minted cookie with drifted attributes or a pre-auth identifier reused post-auth. Mitigation: D-02 byte-identical mint from login_submit's exact format string; fresh token signed at callback time; no pre-login identifier exists anywhere. Tests: `sso_callback_cookie_byte_identical_to_password_login`, plus the 17-01 `sso_reg_` suite pinning the password path.
  </threat>
  <threat id="T-17-10" stride="Denial of Service" severity="low">
    State-cookie DoS: state is stateless (signed cookie), so no server memory to exhaust; the 600 s TTL bounds replay windows. Tests: `sso_login_disabled_returns_404` (disabled path costs nothing) + `sso_login_redirects_with_pkce_s256_and_state_cookie` asserts `Max-Age=600` bounding the replay window. Accepted residual: unauthenticated /sso/login costs one URL build — bounded, no new rate-limit surface in v1 (recorded, mirrors Phase 16 per-token acceptance style).
  </threat>
</threat_model>
