<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated/locked user → vault mutation routes | The demo account (or anyone using its session) crosses into load/delete/edit/share mutations |
| config/env → RuntimeConfig | Operator-supplied locked-account list crosses into an authorization decision |
| server-rendered HTML → browser JS | The locked flag and alert string cross into the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Tampering | home popup | mitigate | Popup is UX ONLY — the refusal lives server-side in the handlers; a scripted POST (curl, no JS) is refused with 400; a test proves it without a browser |
| T-12-02 | Elevation of privilege | is_locked helper | mitigate | Case-insensitive email compare (`eq_ignore_ascii_case`) so `Demo@X` cannot bypass `demo@x`; admins never locked is intentional (D-02) and the demo user is a reader |
| T-12-03 | Spoofing | env override | mitigate | `MORINET_LOCKED_ACCOUNTS` is operator-controlled config, same trust level as `MORINET_ADMIN_EMAIL`; entries trimmed + lowercased at resolve time so whitespace/case mistakes cannot silently un-lock an account |
| T-12-04 | Information disclosure | error_page refusal body | mitigate | Fixed static message (the exact popup string), html_escaped by the existing `error_page`; no vault data, no enumeration of who else is locked |
| T-12-05 | Denial of service | load_personal_vault gate | mitigate | Locked check runs before quota/clone so a refused load never touches the network or disk |
| T-12-SC | Tampering | dependencies | accept | No new dependencies in this plan |

Block-on-high: any newly discovered HIGH threat in touched code blocks the plan. ASVS L1 applies.
</threat_model>
