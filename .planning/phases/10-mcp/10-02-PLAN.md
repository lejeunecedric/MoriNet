# PLAN 10-02 — MCP StreamableHttp sur /mcp (rmcp)

**Type**: vertical slice (auth middleware → server rmcp → 4 tools → tests E2E). TDD obligatoire.
**Depends on**: 10-01 (user_for_api_token).

## Objectif

Un client MCP (ex. `mcp-cli`) peut se connecter à `https://…/mcp` avec
`Authorization: Bearer mn_…` et découvrir/utiliser 4 tools sur les vaults accessibles.

## Changes

1. `Cargo.toml` — `rmcp = { version = "3.7", features = ["server", "transport-streamable-http-server"] }`.
2. `src/mcp.rs` (nouveau module) —
   - `struct MoriMcp { store, data_dir }` impl `ServerHandler` (`#[tool(tool_box)]`),
     stateless : le user du request courant est passé au factory (voir point 3) OU capturé
     via un `RequestContext` — trancher en impl, sinon stateless par-request avec le claims
     injectés par le middleware.
   - Tools (tous scoped ACL via `list_vaults_for` / `acl_allows`) :
     - `list_vaults()` → [{slug, name, scope}]
     - `list_notes(slug, path?)` → liste des `.md` sous la source (arborescence relative)
     - `read_note(slug, path)` → contenu markdown (safe_join, refus `..`/absolu)
     - `search_notes(query, slug?)` → matches insensibles à la casse dans les `.md`
       accessibles, [{slug, path, line, snippet}], borne raisonnable (ex. 50).
   - Erreurs d'outil (vault inconnu/sans accès) : `ToolError` générique, pas de distinction
     403/404 (pas de fuite d'existence).
3. `src/server.rs` —
   - Middleware Bearer sur `/mcp` : `Authorization: Bearer mn_…` → `user_for_api_token` ;
     absent/invalide → 401 JSON-RPC-ish. Les cookies de session NE sont PAS acceptés ici.
   - Montage : `StreamableHttpService::new(factory, LocalSessionManager::default().into(),
     StreamableHttpServerConfig::default().with_legacy_session_mode(false).with_json_response(true))`
     en `nest_service("/mcp", …)` — le factory capture un handle clonable (store pool).
   - Le user authentifié par Bearer doit atteindre les tools : en stateless, relire le
     header dans le handler via un ext layer qui dépose l'email dans request extensions.

## Tests (RED d'abord)

- Unit `src/mcp.rs` : `search_notes` sur un corpus temp (fixture) — trouve, insensible à la
  casse, borné ; `read_note` refuse `../` et chemins hors source ; `list_notes` trie.
- ACL : un user sans accès au slug reçoit une erreur d'outil sur les 4 tools (fixture store).
- E2E (tower::ServiceExt oneshot sur le router) : POST `/mcp` initialize + tools/list sans
  Bearer → 401 ; avec Bearer valide → la liste contient les 4 tools ; tools/call
  `list_vaults` ne retourne que les vaults accessibles.
