<objective>
Ship REQ-VLT-013: the boot-seeded global "MoriNet Documentation" vault. Six English, user-facing pages are embedded in the binary with include_str!, written on first boot to <data_dir>/docs/morinet-docs/ as a native mdBook source (book.toml + flat src/SUMMARY.md), built through the normal mdbook pipeline, registered via seed_vault (scope defaults to global) and granted read to every group with plan 01's grant_vault_to_all_groups. A version marker file makes the seed strictly once-only so operator edits are never overwritten.

Maps to ROADMAP Phase 10.1 criterion "Default docs vault … seed idempotent, contenu embarqué dans le binaire … appears in 'Shared with me' on first login" and REQ-VLT-013.

Native mdBook layout is chosen deliberately over the llm-wiki conversion path: a flat SUMMARY of 6 top-level entries avoids mdBook 0.5's nested-draft rejection (pitfall #19) and title-sanitization traps (pitfall #21) — the docs vault must never be the vault that fails to build.
Output: `docs/morinet-docs/**` content, new module `src/docs_seed.rs`, `pub mod docs_seed;` in lib.rs, boot wiring in main.rs, tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| binary → data_dir filesystem | embedded content is written to disk at boot |
| boot → mdbook subprocess | seed invokes an external binary |
| operator edits → seed sweep | re-seeding could silently destroy operator content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10.1-15 | Tampering | seed overwrite of operator edits | mitigate | version marker short-circuits all writes after first seed; write_source_tree additionally never overwrites existing files |
| T-10.1-16 | Denial of service | mdbook missing/hang aborting boot | mitigate | seed failure is warning-only in main.rs (same contract as the existing vault-sync warning); docs vault absence never blocks the server |
| T-10.1-17 | Information disclosure | docs content leaking internal details | mitigate | content is reviewed user-facing English (no credentials, no internal GSD jargon, no live hostnames — asserted by the no-hardcoded-host grep) |
| T-10.1-18 | Tampering | path handling in write_source_tree | accept | all paths are compile-time constants joined under data_dir; no user input reaches the writer |
</threat_model>
