## What was built

- **T1 — Index 3 sections**: single `fn vault_row(a: &AccessibleVault, can_share: bool) -> String` helper, two call sites → structural parity between "My vaults" and "Shared with me" is impossible to break. "Load a vault" is its own panel (form + `AUTOFILL_NAME_JS` moved verbatim). h1 "Vaults". Tests: `index_has_three_sections`, `index_row_parity_between_sections`, `index_shared_writer_row_has_refresh`, `index_shared_reader_row_has_no_refresh_no_edit`.
- **T2 — Edit page** `/vault/{slug}/edit` (GET/POST, owner-or-admin gate `can_edit_vault`): rename + source URL (set only when non-empty) + `allow_reshare` checkbox. Tests: `edit_page_owner_shows_form`, `edit_page_sharee_forbidden`, `edit_submit_renames_resources_and_sets_reshare`, `edit_submit_without_checkbox_clears_reshare`.
- **T3 — Share pages**: GET `/vault/{slug}/share` (list + add form + pending hint for unknown emails + revoke + hidden marker, gated by `can_share`), POST add/revoke/hide (`hide` = per-sharee hidden flag). All share strings html-escaped.
- **T4 — Stats + logging**: GET `/vault/{slug}/stats` — owner/admin full panel (Pages, human disk size, Last refresh/sync, Source, per-day web/mcp table, Top pages); any non-owner WITH access sees ONLY "You have accessed this vault N time(s)" (negative assertions in tests); no-access 403. `log_web_access` fire-and-forget `tokio::spawn` on 200-serve paths only. Helpers `dir_size_bytes`/`human_size` + unit tests. WebDAV share route tests: writer PUT ok, reader 403, hidden no-access.

## Deviations

## Decisions

- Non-owner stats access proven via `accessible_vaults` entry (direct_share or group grant) — one ACL source of truth, no second share-table query in the handler.
- `can_edit_vault` = admin via `role_for` OR owner via personal row in `accessible_vaults` (plan-sanctioned local helper).
