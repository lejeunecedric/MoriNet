# Phase 10.1: Home UX — vault actions, share by email, statistics - Context

**Gathered:** 2026-10-25
**Status:** Ready for planning

<domain>
## Phase Boundary

The landing page becomes the vault cockpit, and sharing becomes user-facing:
- Index = 3 sections: "My vaults" / "Shared with me" (identical rendering) / "Load a vault" (own section)
- Per-vault actions: Edit, Refresh, Delete, Share, Statistics
- Direct user-to-user sharing by email with roles + owner-controlled re-share
- Per-vault statistics page fed by a best-effort access log (web + MCP)
- Boot-seeded global "MoriNet Documentation" vault visible to every user

Requirements: REQ-VLT-009..013 (REQUIREMENTS.md). Not in scope: group-based
sharing UI (admin keeps current /admin perms), usage analytics beyond counts,
notifications on share.
</domain>

<decisions>
## Implementation Decisions

### Index layout
- Keep the **current list-row style** extended with an action-button row per vault (no card grid, no new CSS paradigm). Reuse existing `btn-ghost`/`btn-quiet` classes per the design system (pitfall: design system stabilized — no gratuitous CSS).
- Three sections, same markup helper for both vault lists (parity is structural: one render function, two call sites): "My vaults", "Shared with me", "Load a vault" (moved out of the My-vaults panel; keep AUTOFILL_NAME_JS behavior).
- Action buttons on own vaults: Edit, Refresh, Delete, Share, Statistics. On shared vaults: same set, gated by role/permissions (see below).

### Share (direct by email)
- New table `vault_shares` (vault_slug, email, role reader|writer, allow_reshare inherited from vault or per-share — planner picks simplest consistent with the vault-level toggle, created_at).
- Vault-level `allow_reshare` toggle owned by the vault owner (part of Edit). A sharee may re-share only when it is on.
- **writer role = web read + WebDAV write + Refresh button** (refresh allowed for writers). reader = web read only.
- Sharee can **Remove from my view**: per-share `hidden` flag — hides the row for that sharee only; the share stays active (owner's share list unchanged). Owner can revoke a share outright.
- Sharing with an unknown email: allowed (email may register later) — the share resolves when that user logs in. Show owner a "pending" hint if no user with that email exists yet.
- `accessible_vaults` = union(group grants, direct shares not hidden); WebDAV and MCP honor the same union (MCP tools already go through accessible_vaults — verify).

### Edit
- Rename vault + change GitHub source URL + `allow_reshare` toggle. Editing the source URL means next Refresh pulls the new repo (store already has `set_vault_source`).
- UI: small edit form page `/vault/{slug}/edit` (owner only) — planner may choose inline instead, but must keep index uncluttered (one primary action per row rule).

### Statistics
- Page `/vault/{slug}/stats`. **Owner sees full stats** of their vaults: page count, disk size, last refresh, source URL, access counts per day (web vs MCP), top pages.
- **A sharee sees only their own access count to that share** (nb of times they accessed it) — nothing else.
- New `access_log` table (vault_slug, email, source web|mcp, path, ts). Logging is **best-effort**: spawn/ignore errors, never fail or slow the request (fire-and-forget task or best-effort insert). Prune rows older than 90 days at boot (simple DELETE).
- Wire into `vault_index`/`vault_file` (web) and the 4 MCP tools (mcp.rs).

### Default docs vault (REQ-VLT-013)
- Boot seed `morinet-docs` ("MoriNet Documentation"): global vault granted to all groups (boot sweep like `ensure_default_memberships`), built from markdown embedded with `include_str!` (docs written in English, 6 pages: Quick start, Config reference, WebDAV, MCP, Sharing & roles, FAQ).
- Idempotent: never overwrite the seeded pages if the operator edited them; seed once (e.g. marker/version file). Pages must go through the normal build pipeline (mdbook) so Refresh/serve behave identically.

### Testing
- Accepted deviations (acknowledged 2026-10-25): admins may use owner-only surfaces (Edit/Share/full stats) — they already hold global Write; `last_refreshed_at` also stamps boot config-sync, so the stats label reads "Last refresh/sync".
- Store-level tests: share/reshare/hidden/revoke matrix; accessible_vaults union; stats aggregation query.
- Handler tests: share form requires owner (or reshare-permitted), stats visibility split (owner full vs sharee own-count), index renders 3 sections with identical markup for both lists.
- Keep `cargo test --lib` green; clippy -D warnings clean.
</decisions>
