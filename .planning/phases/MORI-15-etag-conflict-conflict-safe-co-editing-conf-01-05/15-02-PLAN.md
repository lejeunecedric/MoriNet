<threat_model>
  <abuse case="info leak via actor column">
    `actor` stores a user email in the audit table. It is only rendered on the
    ACL-gated vault stats page (Phase 13 surface) and the owner-only conflict
    response (15-04) — never on public pages. Mitigation: existing stats-page
    access gate is the disclosure boundary; no new public query path added.
  </abuse>
  <abuse case="migration breaks existing installs / data loss">
    Additive ALTERs with NOT NULL DEFAULT only; no table rebuild, no CHECK
    change (D-05). sqlx migrate runs each file once. Mitigation: test inserts
    a row without the new columns and reads defaults back.
  </abuse>
  <abuse case="SQL injection via new query">
    `vault_changes_for_path` uses bound parameters only (`?` placeholders),
    path is never interpolated into SQL. Mitigation: house query_as style with
    binds; acceptance grep shows no `format!` around SQL.
  </abuse>
</threat_model>
