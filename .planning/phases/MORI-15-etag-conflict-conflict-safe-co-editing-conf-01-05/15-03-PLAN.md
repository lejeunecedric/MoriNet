<objective>
Enforce `If-Match` / `If-None-Match` on WebDAV PUT (412/400, nothing written,
no rebuild, no vault_changes row on failure), return the new ETag on success,
populate `actor` on PUT audit rows (D-06), and make check→write race-safe via
ONE shared atomic write helper + per-vault in-process lock (ROADMAP criterion 7,
pitfalls C3/C5) — while unconditional PUT behaves exactly as before (CONF-05).
</objective>

<threat_model>
  <abuse case="precondition bypass (write despite If-Match mismatch)">
    Evaluation happens inside the per-vault lock against the hash of the bytes
    on disk at that instant, before any write; Malformed headers fail closed to
    400 (never a silent write — C2). Mitigation: lock-scoped check→write,
    412/400 tests assert bytes unchanged.
  </abuse>
  <abuse case="TOCTOU between check and write (C3)">
    Two concurrent PUTs both passing the check. Mitigation: per-vault
    tokio Mutex serializes check→write within the process (single binary —
    sufficient per C3); `write_source_atomic` temp+rename makes each write
    atomic so no interleaved/truncated files; hash returned is recomputed from
    the bytes written.
  </abuse>
  <abuse case="info leak via 412 body">
    The 412 body names the current ETag. Only reachable after
    `access.can_write()` passed — the requester already has write (hence read)
    access to the file, so the hash discloses nothing they cannot GET.
    Mitigation: precondition evaluation strictly after authz (test asserts
    FORBIDDEN precedes any 412 for a no-write user).
  </abuse>
  <abuse case="path traversal via PUT / temp file name">
    `safe_join` unchanged and still gates the target path; the temp file name
    is derived from the already-sanitized file_name with a uuid suffix in the
    same directory — no user-controlled traversal in the temp path.
    Mitigation: existing traversal tests green; temp file never leaves src_dir.
  </abuse>
  <abuse case="DoS via lock contention / huge bodies">
    Body cap stays 8 MiB; the lock is held only for read-hash + atomic write
    (milliseconds), released before rebuild. Mitigation: bounded critical
    sections; no new unbounded allocation.
  </abuse>
</threat_model>
