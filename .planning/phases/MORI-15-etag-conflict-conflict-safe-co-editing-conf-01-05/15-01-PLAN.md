Emit strong content-hash ETags (sha256 of raw source bytes) on WebDAV GET and
`getetag` on PROPFIND (CONF-01), and land the pure `If-Match` / `If-None-Match`
header parsers that 15-03 will enforce. One hash helper feeds every consumer
("one hash, three consumers", FEATURES.md Feature Area 3).
</objective>

  <action>
    In src/webdav.rs add `pub enum Precondition { Absent, Any, Tags(Vec&lt;String&gt;), Malformed }`
    and two pure parsers shaped like `depth_of` but fail-closed: fetch
    `headers.get("if-match")`; header absent → Absent; present but `to_str()`
    fails (invalid UTF-8 bytes) → Malformed — an unreadable precondition
    header is NEVER treated as Absent (C2 fail-closed):
    `pub fn if_match_of(headers: &amp;HeaderMap) -> Precondition` and
    `pub fn if_none_match_of(headers: &amp;HeaderMap) -> Precondition`.
    Parsing rules (planner decision, RFC 9110 §13.1/13.2): absent header →
    Absent; value trimmed == `*` → Any; otherwise comma-split, each token
    trimmed MUST be a quoted string `"..."` — any token starting with `W/`,
    any unquoted bare token, or an empty list → Malformed (fail closed; caller
    turns Malformed into 400 — unlike depth_of, never default on garbage).
    Tags keep the quotes (compared directly against quoted etag_of output).
    Table-driven `#[test]`s in webdav.rs mod tests covering: absent, `*`,
    single quoted tag, comma list with spaces, `W/"x"` → Malformed,
    bare `abc` → Malformed, empty value → Malformed, mixed valid+`W/` →
    Malformed, non-UTF-8 header bytes → Malformed (build the HeaderValue
    from raw invalid bytes).
  </action>

<threat_model>
  <abuse case="path traversal on new read paths">
    No new path handling is introduced; GET/PROPFIND keep using
    `webdav::safe_join` (server.rs :870) unchanged. The hash helper takes
    already-joined `&amp;[u8]`, never a path. Mitigation: reuse of safe_join;
    traversal test suite must stay green.
  </abuse>
  <abuse case="info leak via ETag">
    ETag is a hash of content the requester already read — emission happens
    only after the can_read authz gate (:821-828), so no content is exposed to
    unauthorized users. Mitigation: authz-before-emission ordering asserted by
    existing FORBIDDEN tests.
  </abuse>
  <abuse case="DoS via hashing huge trees in PROPFIND">
    Hash-on-read is O(total bytes) per PROPFIND. Bounded: upload caps files at
    5 MB and PUT bodies at 8 MB, vault trees are user-quota'd, sha256 runs at
    GB/s. Accepted per CONTEXT discretion ("hash-on-read is acceptable").
    Mitigation: no unbounded new input surface; sizes bounded by existing caps.
  </abuse>
  <abuse case="precondition parser panic / bypass via crafted header">
    Parsers are total pure functions returning Malformed instead of panicking
    on any input (invalid UTF-8 header → Malformed → 400, NEVER Absent —
    fail-closed per C2; exercised in tests with a non-UTF-8 HeaderValue). Malformed is fail-closed: caller (15-03) must 400,
    never write. Mitigation: table-driven tests include garbage inputs.
  </abuse>
</threat_model>
