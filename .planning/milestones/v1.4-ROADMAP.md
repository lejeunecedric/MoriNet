1|# MoriNet — Roadmap
2|
3|> Obsidian second brain exposed as an mdbook-like server with multi-user auth, admin UI, vault management (local + GitHub), WebDAV, and MCP. All in Rust, `cargo install morinet`.
4|
5|**Repo**: `github.com/lejeunecedric/MoriNet`
6|**Stack**: Rust stable, axum, sqlx (SQLite), mdbook (CLI upstream), rmcp, lettre
7|**Delivery format**: static binary via `cargo install morinet`

110|## Milestone v1.3: OKF Bundle Support (Phases 18+)
111|
112|**Goal:** MoriNet hosts Open Knowledge Format bundles natively — detect and report OKF conformance of vaults, export any vault as a portable OKF bundle, and expose concept metadata (type/tags/status/trust tier) through the REST API and MCP so agents consume bundles as knowledge graphs, not raw files. (GitHub issue #11; research: `.planning/research/OKF.md`)
113|
114|### Phase 18: okf-bundle-support
115|
116|**Goal:** detect OKF conformance at refresh time with a vault-page badge, one-click "Export as OKF bundle" (zip), and frontmatter metadata surfaced on `/api/v1` + MCP filters.
117|**Requirements:** OKF-01..OKF-04
118|**Success criteria:**
119|1. At refresh/register, vault sources are scanned for OKF conformance (per-file non-empty `type` frontmatter, reserved `index.md`/`log.md` shape, version guess v0.1 vs v0.2); stats persisted and shown on the vault page as a badge ("OKF v0.2 — N/M concepts" or "not an OKF bundle").
120|2. "Export as OKF bundle" download streams a zip of the vault source (files byte-identical), synthesizing a root `index.md` with `okf_version: "0.2"` in-memory when absent; gated by vault read ACL.
121|3. `/api/v1` note list/read expose parsed frontmatter metadata (`type`, `tags`, `status`, derived trust tier per OKF §5.3); MCP list/search accept optional `type`/`tags` filters; ACL semantics unchanged (404 on inaccessible).
122|4. mdBook rendering pipeline unchanged: converter still strips frontmatter (rendered output identical to v1.3.0).
123|5. At most ONE new runtime dependency (archive format only); `scripts/check.sh` green; existing suite green (baseline 493 passed).
124|
125|**Deferred (later phases):** trust-aware page rendering of OKF families (needs Impeccable design pass); Attested Computation execution (security non-starter — spec defers the runtime protocol).

149|## Milestone v1.4: Statistics & Observability (Phases 19–20)
150|
151|**Goal:** Vault owners can see who reads their vaults and how — top viewed pages (web), API/MCP usage, MCP request↔response activity, top search keywords — plus OKF ecosystem quick wins that make MoriNet's conformance externally verifiable and its exports explorable. (GitHub issue #10; research: `.planning/research/OKF-ECOSYSTEM.md`)
152|
153|### Phase 19: statistics-observability
154|
155|**Goal:** every vault read is counted on every surface, and the Statistics page answers "what did people read, ask, and find?"
156|**Requirements:** STAT-01..STAT-05
157|**Depends on:** Phase 18 (REST `?meta=1` search/read surfaces to instrument)
158|**Success criteria:**
159|1. Migration 0014 widens `access_log.source` CHECK (adds `api`; existing `web`/`mcp` history preserved); boot succeeds on upgraded DBs.
160|2. Web page views, REST API note reads/searches, and MCP tool invocations each append an access event; a logging failure never fails the request (best-effort, logged to stderr).
161|3. Statistics page shows a "Top pages" section per vault (web source, ranked, date-range aware).
162|4. Statistics page shows an "MCP activity" section: newest-first two-column list — request (tool, args summary, actor) left, outcome (status, latency, size + short excerpt) right; full response bodies never stored.
163|5. "Top search keywords" section aggregates MCP `search_notes` + REST `search` query terms per vault.
164|6. 90-day boot prune reuses the `vault_changes` convention; `scripts/check.sh` green; existing suite green (baseline 554 passed).

174|3. README shows an OKF conformance badge/claim backed by criterion 1.
