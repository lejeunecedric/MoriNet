7|## v1.4 Requirements
8|
9|### Statistics & observability (issue #10)
10|
11|- [x] **STAT-01**: Owner/admin can trust that every read of their vaults is counted: access events logged across ALL surfaces — web page views, REST API note reads/searches, and MCP tool invocations (`access_log.source` CHECK widened to include `api`; migration 0014 rebuilds the table, preserves history).
12|- [x] **STAT-02**: Owner can see the **top viewed pages** of each vault on the Statistics page (ranked by views, per configurable date range, web source).
13|- [x] **STAT-03**: Owner can browse recent **MCP activity** per vault: each request (tool, arguments summary, actor) paired with its outcome (status, latency, response size + short excerpt) — requests left, answers right, newest first.
14|- [x] **STAT-04**: Owner can see **top search keywords** per vault, aggregated from MCP `search_notes` and REST `search` queries.
15|- [x] **STAT-05**: Logging is best-effort and bounded: failures never break the request path, entries pruned to 90 days at boot (same convention as `vault_changes`), full response bodies never stored (excerpt + size only), API/MCP surfaces keep 404-not-403 ACL semantics (no stats leak for inaccessible vaults).
