<objective>
Wiki-changes capture layer — schema + store + capture (LOCKED decisions D-01..D-05, D-08 in 13-CONTEXT.md): migration `0010_vault_changes.sql` creates the `vault_changes` table (vault_slug, event_id, kind added/modified/removed, path, ts) with a `(vault_slug, ts)` index; `src/store.rs` gains the access_log-shaped insert / grouped-recent query / 90-day prune trio; `refresh_my_vault` captures the clone's HEAD before `src.sync()`, diffs old→new commit trees with git2 after a successful refresh, and inserts one row per changed repo-relative path under one uuid event_id; the WebDAV PUT path records its single known path change; `main.rs` prunes `vault_changes` alongside `prune_access_log`. Every write is best-effort — a logging failure NEVER changes the refresh or PUT response (D-04).

Maps to ROADMAP Phase 13 criterion "New vault_changes table … populated when Refresh rebuilds a vault (git: diff old→new commit; local: hash-diff source tree before/after)" and REQ-CHG-001. The Statistics-page display half (REQ-CHG-002) is plan 13-02.

Purpose: owners can later see what a refresh actually changed.
Output: `migrations/0010_vault_changes.sql`, three store methods, git-diff capture in `refresh_my_vault`, WebDAV PUT hook, boot prune, tests throughout.

Planner discretion calls (locked for the executor):
- **event_id format**: uuid v4 (`uuid::Uuid::new_v4().to_string()`) — `uuid = { version = "1", features = ["v4"] }` is already a dependency (Cargo.toml:39).
- **Store method names**: `log_vault_change(slug, event_id, kind, path)`, `recent_vault_changes(slug, max_events, max_rows)`, `prune_vault_changes()` — mirrors `log_access` / `stats_*` / `prune_access_log`.
- **find_similar (rename detection)**: NOT used — a rename surfaces as one `removed` + one `added` row. Keeps the D-08 vocabulary exact and the diff code minimal; D-01 marks it optional.
- **D-02 call-site decision**: WebDAV PUT records the single known path (modified/added by pre-write existence check); no full-tree hash diff anywhere (see must_haves).
- **Best-effort logging**: `eprintln!("vault-changes: ...")` — `tracing` is NOT a dependency; the repo's established best-effort log style is `eprintln!` (e.g. "webdav: llm-wiki convert failed after PUT", server.rs ~:910).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git repo content → vault_changes.path | File paths from an upstream repo (or a WebDAV PUT body target) are stored as text and later rendered on the stats page |
| HTTP request → vault_changes rows | Refresh/PUT callers cause rows to be written; volume is caller-controlled |
| SQL parameters → SQLite | slug/event_id/kind/path values reach SQL statements |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | Tampering | SQL parameters | mitigate | sqlx bind params ONLY in every vault_changes query (store Task 1); no format!-built SQL; kind additionally locked by the DB CHECK to the three D-08 tokens — no user-controlled SQL is possible |
| T-13-02 | Information disclosure | vault_changes.path | mitigate | Paths are stored as TEXT only (never used as filesystem paths or in queries beyond bind); plan 13-02 html_escapes them at render (same rule as T-10.1-09 for access_log paths) |
| T-13-03 | Denial of service | row volume | mitigate | 90-day prune at boot (D-05) + per-event caps in the reader query (plan 13-02); a refresh writes at most one row per changed file, and only when HEAD actually moved |
| T-13-04 | Elevation of privilege | capture call sites | accept | No new auth surface: capture runs INSIDE the already-gated refresh_my_vault (can_write) and webdav_entry (can_write) handlers — no new routes, no new ACL logic |
| T-13-05 | Tampering | best-effort wrapper | mitigate | D-04 proven by tests: refresh returns SEE_OTHER and PUT returns 201 on the normal path; the insert block is `if let Err(e)` / spawned-task swallow, so no error path reaches the response |
| T-13-SC | Tampering | dependencies | accept | No new dependencies — git2 (vendored-openssl) and uuid v4 are already in Cargo.toml |

Block-on-high: any newly discovered HIGH threat in touched code blocks the plan. ASVS L1 applies.
</threat_model>
