<threat_model>
ASVS level 1. Security enforcement: block on high severity.
- PATH spoofing: the step executes binaries resolved via PATH. Mitigations: (a) strictly optional — only runs if the operator deliberately installed the tools; (b) never auto-installs and never fetches from the network, so the script cannot introduce a binary the operator did not place; (c) same trust boundary the gate already accepts for cargo/rustc/mdbook; documented in the script header. A spoofed validator could only forge a PASS (weaker claim), never escalate beyond what an attacker already on PATH could do.
- Gate weakening: the contract's failure mode is a silently-passing validator. Enforced by acceptance criteria: no `|| true`, failing-stub test must exit non-zero, skip path prints an explicit visible note.
- JSON parsing uses python3 stdlib on the validator's own output — no eval, no shell interpolation of untrusted strings (JSON goes via stdin/file, never re-evaluated by the shell).
Severity: no high-severity threats identified.
