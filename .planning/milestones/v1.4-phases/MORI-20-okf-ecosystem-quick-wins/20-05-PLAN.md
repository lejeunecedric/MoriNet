DECIDED MECHANICS (planner discretion — do not re-open):
- Collision policy: VAULT'S OWN viz.html WINS (skip injection when a root viz.html exists in the walk) — consistency with the only-when-absent index.md precedent (Phase 18 D-06). Byte-identical source files stay byte-identical.
- Synthesis mirrors the upstream generator: substitute `/*__VIZ_CSS__*/` → viz.css bytes, `/*__VIZ_JS__*/` → viz.js bytes, `window.BUNDLE_NAME = __BUNDLE_NAME__;` → JSON string of the bundle name, `window.BUNDLE = __BUNDLE_DATA__;` → JSON document built from the walk. Replace the two `cdn.jsdelivr.net` `<script src>` tags with inline `<script>` blocks containing the vendored cytoscape.min.js / marked.min.js bytes — this is what makes the viewer work offline.
- Data document shape (keep minimal, viewer-compatible): `{"name": <slug>, "concepts": [{"id": <rel path>, "title": ..., "type": ..., "description": ..., "tags": [...]}, ...], "edges": [{"from": <rel path>, "to": <rel path>}, ...]}` — concepts from non-reserved .md files via the existing `frontmatter::split` (title/type/description scalars, tags list); edges from markdown links `[text](target)` whose target resolves (root-relative or relative) to another bundled .md path. Unresolvable links are dropped (spec §5.3: broken links are a feature). If the vendored template's JS expects a different field shape, adapt the JSON to what viz.js actually reads — read viz.js first; record the final shape in the SUMMARY.
- XSS/HTML-injection guard: the JSON is embedded inside a `<script>` block — after `serde_json::to_vec`, escape every `<` as `\u003c` (valid JSON escape) so a concept title/description containing `</script>` cannot break out. This is mandatory, not optional.
- Bundle name for the viewer header: `build_bundle_zip(src)` takes NO slug parameter (the export handler calls `crate::okf::build_bundle_zip(&src)` at server.rs:~3200, path only) — so the name is always the source dir's file name (`src.file_name()` of the canonicalized path). Do not add a slug parameter (out of scope); state this fallback honestly in the code comment. In practice the source dir name matches the vault slug for MoriNet-managed vaults.
